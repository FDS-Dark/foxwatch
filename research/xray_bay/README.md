# X-Ray the Bay: spatial water-quality reconstruction feasibility study

This is an independent research prototype for FoxWatch. It does not touch the FoxWatch application.

The question it tests: using real USGS FLAMe research-vessel measurements in Green Bay, can we hide a survey segment, reconstruct it, check the reconstruction against the hidden truth, and suggest where to sample next?

- **Result:** CONDITIONAL GO. See [RESULTS.md](RESULTS.md).
- **Data:** [DATA_AUDIT.md](DATA_AUDIT.md).
- **Next steps:** [RESEARCH_ROADMAP.md](RESEARCH_ROADMAP.md).

## Layout

```
scripts/
  01_download.py          ScienceBase download + Natural Earth lakes; manifest with SHA-256
  02_audit.py             schema/campaign/variable audit, track maps  -> outputs/audit_summary.json, figures/audit_*.png
  02b_coverage.py         fraction of water within d km of a measurement -> outputs/coverage_audit.json
  xray_common.py          data loading/thinning, spatial folds, models (NN, IDW, RF, HGB, GP), metrics
  03_experiment.py        leave-one-segment-out CV, standard + hard buffers, leaky control -> outputs/metrics/<cfg>.json
  03b_mouth_baseline.py   skeptic's baseline: distance-to-Fox-River-mouth only -> outputs/mouth_baseline.json
  04_demo.py              four-state demo figures, GeoTIFF/GeoJSON exports, sampling suggestions, active-sampling replay
  05_report.py            merges metrics, within-segment skill, summary figures -> outputs/metrics.json, results_table.csv
data/raw/                 downloaded release files (FLAMe_data.csv is git-ignored, 192 MB)
data/processed/           flame_core.parquet (git-ignored, regenerated by 02_audit.py)
figures/                  static PNGs
outputs/                  metrics (JSON/CSV), CV predictions (parquet), geo/ exports
```

## Reproduce

Tested on Linux (WSL2) with Python 3.14, using [uv](https://github.com/astral-sh/uv). It needs CPU only; the full run takes about 25 minutes on 16 cores.

```bash
cd research/xray_bay
uv venv .venv
uv pip install --python .venv/bin/python numpy pandas scipy scikit-learn matplotlib pyproj rasterio shapely geopandas pyarrow

.venv/bin/python scripts/01_download.py
```

### Manual download step

`FLAMe_data.csv` is stored in ScienceBase cloud storage and is only served to signed-in users. `01_download.py` prints these steps:

1. Open https://sciencebase.usgs.gov/manager/item/672e5378d34ea9e450891ffe and sign in (a free login.gov account works).
2. Select `FLAMe_data.csv`, click **Download**, then follow the temporary link.
3. Save the file as `data/raw/FLAMe_data.csv`. It should be exactly 191,928,255 bytes.

### Run the pipeline

```bash
cd scripts
../.venv/bin/python 02_audit.py
../.venv/bin/python 02b_coverage.py
../.venv/bin/python 03_experiment.py
../.venv/bin/python 03b_mouth_baseline.py
../.venv/bin/python 04_demo.py
../.venv/bin/python 05_report.py
```

`03_experiment.py` runs every configuration by default. To run selected ones, name them, e.g. `03_experiment.py GreenBay_2025_Jun__chl_RFU_exo_tau`, or give a campaign name.

To run configurations in parallel, start one process per config with limited threads. Without this, BLAS and joblib threads oversubscribe the CPU and every job slows badly:

```bash
OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 XRAY_JOBS=2 ../.venv/bin/python 03_experiment.py <config> &
```

`04_demo.py` takes an optional `<campaign> <target>`. The default is `GreenBay_2025_Jun chl_RFU_exo_tau`.

All random seeds are fixed. Values from the GP optimiser may differ slightly across BLAS builds.

## Key design choices

| Choice | Why |
|---|---|
| `_tau` variables | Corrected for both the plumbing delay and the sensor response time, so the value best matches the logged GPS position. |
| 100 m along-track median bins | The boat logs at 1 Hz, about 5 m apart. Those rows are not independent samples. |
| Water mask (Natural Earth Lake Michigan polygon) | Excludes the Fox River corridor. A 2-D model of a 1-D river makes no sense. |
| Leave-one-5 km-segment-out | Each fold removes the segment plus 1 km of track on either side (standard). The hard scheme also removes everything within 1.5 km. |
| Log(v + 1) for optical targets | The offset is a fixed constant and is never estimated from the data, so held-out values cannot leak through normalisation. |
| 3 km support radius | Cells farther than 3 km from evidence get **no estimate** (NaN) in every raster and figure. |
